Two-stage locked-manifest correction (2026-09-14)
-------------------------------------------------

Formal execution now accepts only an already-existing `--manifest` and an
output report path. It has no role path, file-hash, or state-dict-hash selector
flags and therefore cannot create and execute a formal manifest in one command.
`prepare_main` / the preparation parser is the separate, non-executing path
that writes a concrete manifest from supplied identities; it opens no model and
runs no episode. Execution re-parses the locked JSON through the strict formal
package constructor, revalidates canonical identity, verifies every file hash
again, and recomputes every loaded `net.state_dict()` hash before an episode.

Local journals and read-only candidate inspection did not establish all four
exact canonical role identities unambiguously. Accordingly no candidate is
blessed here and no locked production manifest is added. Formal execution
fails closed unless a separately prepared, valid manifest is supplied.

The paired result fields are descriptive diagnostics only, never a promotion
or pass/fail rule. For each locked pair `delta=b-a`, the paired mean-difference
95% CI gives `higher` only when `lower > 0`, `lower` only when `upper < 0`,
and `indistinguishable` otherwise (including either endpoint exactly zero).
Each pair emits machine-readable `direction`, `classification`,
`classification_basis`, and `classification_rule`.
