Erratum: PlayerV5 round-1 aux PPO (1789163593) is not an α-only contrast
======================================================================

Status
------

Standalone aux-arm retention gate FAIL remains valid.
Cross-arm attribution to α is NOT valid. No promotion. Do not raise α yet.

This file does not rewrite
docs/journal/1789163593_player_v5_retention_aux_round1.txt.
It marks that report's causal claims.

What still holds
----------------

- Aux arm held agreement failed at update 10 (0.6371 < 0.6499).
- Update 200 agreement 0.6147; survival floors passed.
- Train/held split had no leakage; teacher frames did not enter PPO advantage.
- Checkpoints experimental / production_compatible false; promotion false.

What does not hold
------------------

1. Calibration collected seeds 50000-50007 via dist.sample(), discarded them,
   then update 1 re-collected the same env seeds after consuming global torch
   RNG. Calibration batch 14,690 frames matched unregularized update 1;
   aux update 1 had 12,488 frames. Training trajectories differed by more
   than α.

2. Alpha used full-batch PPO policy grad vs 512-frame retention grad, so the
   logged 0.15 target was not the optimizer-step scale (jsonl ratio 0.17-0.49).

3. Snapshot grad_alignment shared the retention generator with training, so
   snapshot schedule could change later aux minibatches.

4. Survival 35.36s vs unregularized 24.53s at update 200 is an observed
   outcome of one run each, not a causal α effect.

5. Snapshot grad_alignment was recomputed AFTER the update's optimizer steps,
   against that update's pre-update rollout batch. Snapshot g_ppo/cosine
   therefore described post-update weights evaluated on an off-policy batch,
   not the on-policy alignment of the step that was taken. Logged per-update
   jsonl grad fields were already pre-update and are unaffected.

6. grad_alignment itself compared a full-rollout PPO policy gradient against a
   512-frame retention gradient, the same scale mismatch as item 2. Every
   snapshot/per-update grad_ratio and cosine_similarity in that run is a
   mismatched-size comparison.

Code fix (not this run)
-----------------------

Commit 7b1c6ce4ef6663ea7dcfbb6d82a3a4a58e275a65:

- Calibration window is collected once and reused as update 1.
- Separate calibration / diagnostic / training generators.
- Alpha averages 8 matched PPO/retention minibatch pairs (up to 512 frames;
  both shrink to the available PPO-frame count for shorter rollouts); target
  ratio still 0.15.

Follow-up fixes (also not this run), addressing items 5 and 6:

- grad_alignment now draws a minibatch-sized PPO subsample, so g_ppo and g_ret
  are measured on equal sample counts. When a rollout window holds fewer
  frames than the minibatch, both draws shrink to the available PPO frames.
- ppo_aux_update returns its pre-update, on-policy alignment probe; snapshots
  store that value instead of recomputing one after the optimizer steps.
  Snapshot 0 still computes its own probe (no update has happened yet).
  Each recorded alignment carries explicit measurement semantics
  ("pre_update_on_policy" / "initial_on_policy", measured_before_update,
  recomputed_post_update=false).
- Matched PPO/retention minibatch behaviour and the three independent RNG
  streams are unchanged.

These change the meaning of future grad_ratio / cosine_similarity numbers.
Values recorded in run 1789163593 are kept as-is and are not comparable to
values produced after these fixes.
