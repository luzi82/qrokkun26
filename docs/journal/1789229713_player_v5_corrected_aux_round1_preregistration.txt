目標與可否證假說
--------------------

目標是在不改變未正則化 PPO 對照的起點、資料、seed window、budget 與 PPO knobs
下，測試唯一新加入的 BC-retention auxiliary objective 是否令最後 snapshot 通過
預先登記的 retention gate。

假說：從指定 seed-6 BC state 開始，於 200 次更新後，輔助項可同時使 final
deterministic mean 與 median survival 各不少於 update 0 的 80%，且 held teacher
agreement 的絕對下降不多於 0.05。若任何 final 條件不成立、held agreement 缺失，
或 initial gate 不通過，假說即 FAIL（initial gate 情況為 fail closed、arm 不跑）。
這是可否證的 retention 假說；不以中途 survival、單一 seed、calibration cosine
或任何漂亮 snapshot 改寫判定。

唯一新目標與校準
----------------

唯一新增訓練目標是每個 PPO minibatch 的
`total = policy_loss + 0.5*value_loss - 0.02*entropy + alpha*hybrid_loss`。
其中 `hybrid_loss` 必須直接使用
`phase2_ranked_multiseed.hybrid_loss`：hard CE weight=0.5、soft teacher CE
weight=0.5、temperature=1。沒有其他新增或可調 knob。

`TARGET_RETENTION_GRAD_RATIO=0.15` 是起始 checkpoint 的「加權 retention
gradient norm／PPO policy-gradient norm」目標，不是 alpha。alpha 是衍生係數：在
任何 optimizer step 前，使用 update-1 的 on-policy rollout、8 個 matched
PPO/retention gradient pairs（`CALIBRATION_GRAD_SAMPLES=8`），每 pair 的共同樣本數
為 `min(512, PPO rollout frames, TRAIN frames)`；任一側為空即 fail closed。對八個
pair 分別求 policy-loss-only（無 value、無 entropy）`||g_ppo||` 與 hybrid
`||g_ret||`，取平均後一次計算並凍結：

`alpha = 0.15 * mean(||g_ppo||) / (mean(||g_ret||) + 1e-8)`。

不得按 evaluation、survival、agreement、KL、cosine 或中途結果重調 alpha。校準
window 正是 update-1 使用的同一批 rollout：只收集一次、原樣重用，沒有丟棄或重收集。
retention sampling streams 必須彼此獨立：training seed=12345、calibration seed=22345、
diagnostic seed=32345；PPO minibatch permutation stream 亦不可與它們共用。這保證
snapshot／diagnostic 的增減不會移動後續訓練 retention draws。snapshot 0 的 alignment
記為 `initial_on_policy`；其後 snapshot 必須重用各 update 已在 optimizer step 前取得的
`pre_update_on_policy` alignment，禁止事後以 post-update weights 重算。

Gates、配對解讀與決策
----------------------

首先只對初始 checkpoint 做 30-seed deterministic eval。initial gate 為 mean >=25.0 s
且 median >=25.0 s；任一失敗即寫出 `failed_closed` report，`arm_ran=false`，不收集
teacher dataset、不校準、不訓練。若起點與已登記基準一致，initial eval 應重新量得
34.0906 s mean、36.7917 s median；dataset 收集後的 update-0 held agreement 應為
0.6999。這些是待核對基準而非本輪結果。

成功 initial gate 後，update 0 是 retention reference。final PASS 必須同時滿足：

- mean >= 0.80 × update-0 mean（相同基準的 floor=27.2724 s）；
- median >= 0.80 × update-0 median（floor=29.4333 s）；
- 每個 snapshot 都有 held agreement，且 final held agreement >= update-0 agreement
  -0.05（相同基準的 floor=0.6499）。

對每個 snapshot，同一 eval seeds 與 update 0 配對，記錄每-seed elapsed 差、paired
mean／median 差、improve/worsen/unchanged counts 與 approximate paired 95% t interval；
此為解讀 survival 變化的配對證據，不取代 gate。必須報告 first breaking snapshot；
任何 snapshot 的 mean、median、agreement（或 agreement 缺失）越界均是第一個
breaking 候選。總 verdict 仍由 final 三條件決定，agreement 缺失 fail closed。

PASS：完整保留 provenance、全部 snapshot、gates 與 accounting，並仍 promote nothing；
只有另立預先登記文件後才可考慮下一個比較。FAIL：完整保留失敗報告與全部實驗
snapshots，promote nothing；禁止從曲線事後選 alpha 或 checkpoint。任何新假說必須是
另一份 preregistration，且只含一項明確改動。

預期執行命令
------------

在 repository root、已核對的 clean checkout、且上述三個值皆指向本機副本時執行：

```bash
PYTHONPATH=. python -m tools.phase3_ranked_ppo_retention_aux \
  --init-checkpoint "${INIT_CHECKPOINT}" \
  --teacher "${TEACHER}" \
  --out-dir "${OUT_DIR}" \
  --device cuda
```

`${INIT_CHECKPOINT}`、`${TEACHER}`、`${OUT_DIR}` 是啟動時才填入並記錄的
execution-host paths；不得填 NAS path，且不可加入 `--quick`。
